# ۲. تطبیق قابلیت‌های پیاده‌سازی‌شده با پروپوزال

وضعیت هر بند پروپوزال با توجه به کد واقعی موجود در مخزن (شاخهٔ `security/auth-review`):

| بند پروپوزال | وضعیت | محل پیاده‌سازی |
|---|---|---|
| مدیریت کاربران ( ایجاد، ورود، نقش‌ها، فعال/غیرفعال) | کامل | `app/auth/*`، `app/routers/users.py` |
| هش امن رمز (Argon2id) و توکن JWT | کامل | `app/auth/security.py` |
| ورود بیمار بدون رمز (OTP یک‌بارمصرف با محدودیت) | کامل | `app/auth/otp.py` |
| مدیریت نقش‌های admin / receptionist / doctor / patient | کامل | `app/auth/permissions.py` |
| کنترل دسترسی در تمام endpointها و ابزارهای Agent | کامل | نقطه‌ی واحد `app/auth/permissions.py`؛ تست: `tests/test_permissions.py`، `test_link_and_idor.py` |
| اتصال امن حساب بیمار به پرونده (پیوند توسط پذیرش/مدیر) | کامل | `POST /patients/{id}/link-user` + unique index |
| جلوگیری از دسترسی بیمار به پرونده/نوبت بیمار دیگر (IDOR) | کامل | اجازه‌ها سمت سرور؛ تست IDOR |
| پرونده پایه بیمار (ایجاد، مشاهده، اصلاح، حذف) | کامل | `app/routers/patients.py`، `patient_service.py` |
| جستجوی بیمار با معیارهای مجاز | کامل | `GET /patients/?search=...` (فقط نقش‌های مجاز) |
| جلوگیری از پرونده تکراری (کد ملی یکتا) | کامل | unique + `PATIENT_DUPLICATE_NATIONAL_ID` |
| فهرست و مشاهده پزشکان و خدمات | کامل | `GET /doctors`، `GET /dental-services` |
| مدیریت اطلاعات پزشک/خدمات با نقش مجاز (admin) | کامل | CRUD در `doctors.py`, `dental_services.py` |
| نمایش نام واقعی پزشک و خدمت (نه شناسه داخلی) | کامل | پاسخ‌های enriched + رابط؛ تست `app_smoke.js` |
| برنامه‌ی زمانی پزشک و تولید slot | کامل | `doctor_schedules.py`, `appointment_service.py` |
| رزرو / لغو / جابه‌جایی نوبت | کامل | گردش‌کار تراکنشی + تست `appointment_http_flow` |
| جلوگیری از رزرو هم‌زمان یک زمان | کامل | partial unique index + recheck اتمیک؛ تست `test_appointment_slot_uniqueness.py` |
| اعتبارسنجی وضعیت نوبت و مدیریت نوبت لغوشده/گذشته | کامل | کد خطاها: `APPOINTMENT_*` |
| مشاهده نوبت‌ها برای کارکنان در محدوده مجوز | کامل | `GET /appointments/` (پزشک فقط رکورد خود) |
| مشاهده نوبت‌های شخصی بیمار بدون شناسه داخلی | کامل | `GET /appointments/me` |
| تاریخ شمسی و منطقه زمانی (Asia/Tehran) صحیح | کامل | `app/utils/date_utils.py`, `clinic_now` |
| Agent: تحلیل درخواست، انتخاب ابزار، مجوز سمت سرور، تأیید صریح، اجرای کنترل‌شده | کامل | `app/agent/graph.py` (گره‌ها و مسیریابی) + `app/agent/{patient_binding,confirmation_text,outcomes}.py` + `agent_tools/` |
| ابزارها با schema مشخص و اعتبارسنجی ورودی | کامل | Pydantic در `agent_tools/schemas.py` |
| عدم پذیرش `patient_id` از سمت مدل برای بیمار | کامل | `PATIENT_BOUND_FIELDS` + injection سمت سرور |
| تأییدیه یک‌بارمصرف bound به کاربر/نشست/ابزار/آرگومان | کامل | `app/agent/confirmations.py` + گیت تأیید در `graph.py` و متن تأییدیه در `confirmation_text.py` |
| خطاهای مدل/timeout/پاسخ نامعتبر بدون نشت اطلاعات | کامل | پیام‌های کاتالوگ‌شده; تست `test_agent_hardening.py` |
| وب‌سایت فارسی RTL نقش‌محور (ورود، داشبورد، بیماران، نوبت‌ها، پزشکان/خدمات، دستیار) | کامل | اپ React در `webapp/` (build شده در `/app`)؛ `web/` صفحهٔ جایگزین (legacy) |
| پنل گفت‌وگوی دستیار + تأیید عملیات + کارت نوبت‌ها | کامل | صفحهٔ «دستیار» و کشوی دستیار در `webapp/` (جایگزین: `web/index.html`) |
| تاریخچه چت فقط در محدوده همان کاربر | کامل | ذخیرهٔ سمت سرور (`chat_history.py`)؛ همهٔ پرس‌وجوها با `user_id` فیلتر می‌شوند؛ `/agent/conversations` |
| مایگریشن افزایشی سازگار با داده موجود | کامل | `app/db_migration.py` (شامل ستون جدید `doctors.user_id`) |
| پوشش کاربردی Agent (جزئیات زیر) | کامل | ابزارهای اجازه‌گرفته |

## موارد عمداً پیاده‌سازی‌نشده (ثبت‌شده، نه فراموش‌شده)

- صفحه اختصاصی «مشاهده پرونده بیمار» جدا از فهرست بیماران — نمایش اطلاعات پایه در همان جدول بیماران انجام می‌شود (مطابق دامنه محدود پروپوزال).
- ویرایش جزئی برنامهٔ زمانی پزشک (ساعات) در رابط — ایجاد/حذف برنامه پیاده شده؛ ویرایش جزئی به API موجود مانده است.
- دستیار Admin/Support Agent (مانیتورینگ/عیب‌یابی) — خارج از دامنه پروپوزال؛ پیشنهاد توسعه در سند ۱۰.
