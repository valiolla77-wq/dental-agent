# ۵. نقش‌ها و ماتریس مجوزها

تعریف مجوزها فقط در یک نقطه اعمال می‌شود: `app/auth/permissions.py`. این همان ماتریسی است که هم HTTP و هم ابزارهای Agent از آن استفاده می‌کنند. نقش‌های ناشناخته «بدون مجوز» در نظر گرفته می‌شوند (fail-closed).

## سربارگذاری دسترسی در سطح حساب (نسخهٔ جدید)

علاوه بر ماتریس نقش، مدیر می‌تواند برای هر حساب پذیرش/پزشک چند عملیات را صریحاً «اجازه» یا «رد» کند (`users.permission_overrides`, JSON):

- اثر ترتیبی: `allow`/`deny` همیشه بر پیش‌فرض نقش مقدم است؛ بدون override همان پیش‌فرض اعمال می‌شود.
- فقط برای نقش‌های `receptionist` و `doctor` معتبر است؛ برای `admin` اثر ندارد (مدیر همیشه کامل است تا کلینیک هرگز از سیستم قفل نشود) و برای `patient` هم ممنوع (قواعد مالکیت حاکم می‌مانند).
- endpointهای مدیریتی: `GET /users/{id}/permissions` (نمای اثر نهایی برای UI) و `PUT /users/{id}/permissions` (جایگزینی کامل overrideها؛ آبجکت خالی = بازگشت به پیش‌فرض نقش).
- تغییر سمت حساب، همهٔ overrideها را پاک می‌کند تا دسترسی پین‌شدهٔ سمت قبلی به سمت جدید منتقل نشود.
- هر تغییر در گزارش حسابرسی (`user.permissions.update`) ثبت می‌شود.

## قواعد مالکیت (سرور-ساید)

1. هویت کاربر همیشه از توکن JWT خوانده می‌شود؛ هیچ ورودی کلاینت/مدلی نقش یا هویت را تعیین نمی‌کند.
2. بیمار با حساب متصل فقط رکورد و نوبت‌های خودش را می‌بیند؛ تلاش برای آیدی دیگر = `COMMON_FORBIDDEN` (۴۰۳) بدون افشای وجود آن رکورد.
3. حساب بیمار بدون پرونده متصل: روی `/appointments/me` خطا `PATIENT_ACCOUNT_NOT_LINKED`؛ شامل پیام راهنمای تماس با پذیرش.
4. حساب پزشک بدون رکورد متصل: روی لیست نوبت‌ها خطا `DOCTOR_ACCOUNT_NOT_LINKED` (۳).
5. پیوند فقط با انطباق تلفن + نقش مجاز + عدم پیوند قبلی ممکن است؛ یکتایی با unique index پایگاه داده تضمین می‌شود.
6. مدیر نمی‌تواند حساب خودش را غیرفعال یا نقش خودش را کاهش دهد (جلوگیری از قفل‌شدن کل سیستم).
7. حفاظ «آخرین مدیر فعال»: غیرفعال‌کردن/تنزل/حذفِ تنها مدیر فعال با `USER_LAST_ADMIN_PROTECTED` (۴۰۹) رد می‌شود؛ حذف حسابِ خودِ مدیر هم ممنوع است.
8. حذف حساب، ارجاع‌های نرم (پروندهٔ بیمار/پزشک متصل، گفتگوها، تأییدیه‌ها، بازخورد) را جدا می‌کند و خودِ حذف در گزارش حسابرسی می‌ماند.
9. گزارش حسابرسی (`audit_logs`) فقط-افزودنی است: هیچ endpoint ویرایش/حذف ندارد.

## محدودسازی نقش پزشک

پزشک برای مطالعه به کل رکوردهای بیماران دسترسی خواندن دارد (مطابق نیاز بالینی)، اما در لیست نوبت‌ها خروجی فقط شامل نوبت‌های **خودِ رکورد پزشک متصل** است. ویرایشی (رزرو/لغو/جابه‌جایی) برای این نقش مجاز نیست.
