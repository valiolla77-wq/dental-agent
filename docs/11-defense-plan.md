## اسکریپت نمایش (قبل از جلسه آماده کنید)

1. `uvicorn app.main:app --port 8000` و اجرای `python scripts\seed_sample.py` (یکبار).
2. مرورگر: `/app` → ورود پذیرش → تب «دستیار» → «نزدیک‌ترین نوبت‌ها» → انتخاب slot → تأییدیه appears → تأیید → «نوبت‌ها» برای مشاهده نتیجه واقعی.
3. تب «بیماران»: جستجو + ثبت بیمار جدید.
4. خروج → ورود بیمار با OTP (`dev_otp` در `APP_ENV=development`) → «نوبت‌های من» → لغو نوبت خود.
5. خروج → ورود پزشک (حساب پیوندشده) → تب «نوبت‌ها» شروع‌شده از انتخاب قفل‌شده doctor خودش.

## پرسش‌های محتمل و پاسخ کوتاه

**Q: چرا Agent «واقعی» است؟** — مدل از میان ابزارهای اجازه‌گرفته با `bind_tools` انتخاب می‌کند؛ تصمیم و خروجی از نتایج واقعی ابزارها و DB ساخته می‌شود؛ تست‌های `test_agent_hardening.py` نشان می‌دهند بدون تأیید هیچ write رخ نمی‌دهد حتی اگر مدل اصرار کند.

**Q: چطور از نشت داده جلوگیری شده؟** — سه‌لایه: (۱) مجوز متمرکز HTTP+Agent، (۲) هویت فقط از JWT، (۳) پاک‌سازی آرگومان‌ها از تاریخچه و عدم ارسال شناسه‌های داخلی به کلاینت؛ تست‌های IDOR و حریم کاتالوگ.

**Q: اگر مدل نبود، سیستم چطور؟** — backend و UI بدون LLM کامل کار می‌کنند؛ chat فقط پیام `AGENT_PROVIDER_NOT_CONFIGURED` می‌دهد (bug نیست، رفتار تعریف‌شده است).

**Q: معماری داده؟** — ERD بخش ۴؛ نکته کلیدی index یکتای جزئی روی `(doctor_id, appointment_time) WHERE status='scheduled'` + recheck اتمیک در تراکنش، برای ممنوعیت رزرو هم‌زمان.

**Q: چرا بدون فریم‌ورک SPA؟** — الزام «backend منبع حقیقت» و «رابط سبک»؛ یک صفحه RTL ساده، بدون build step، بدون وابستگی npm در runtime.
