# Dental Agent — دموی دانشگاهی

سامانه مدیریت مطب دندان‌پزشکی با دستیار ایجنت فارسی. بیمار از صفحه چت می‌تواند زمان آزاد را ببیند، درخواست رزرو/لغو/جابه‌جایی بدهد، پیشنهاد را تأیید یا رد کند و نتیجه واقعی را در دیتابیس ببیند.

> این پروژه یک دموی دانشگاهی است. SMS واقعی ارسال نمی‌شود و رمزهای نمونه فقط برای دمو هستند. هرگز از دیتابیس Production یا بکاپ واقعی برای این دمو استفاده نکنید.

## پیش‌نیازها

- Python 3.11
- دسترسی به یک سرویس LLM سازگار با OpenAI (در دموی فعلی: 9router روی `http://localhost:20128/v1`)
- مدل تنظیم‌شده در `.env` (نمونه: `cx/gpt-6-luna`)

## ۱. نصب

از ریشه پروژه:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## ۲. تنظیمات محیطی

فایل `.env.example` را به `.env` کپی کنید و مقادیر را در همان فایل محلی تنظیم کنید. `.env` در `.gitignore` است و نباید Commit شود.

حداقل متغیرهای لازم:

```dotenv
DATABASE_URL=sqlite+aiosqlite:///./demo.db
JWT_SECRET=<یک مقدار تصادفی طولانی و محرمانه>
CONFIRMATION_HMAC_SECRET=<یک مقدار تصادفی مستقل و محرمانه>
APP_ENV=development
OTP_PROVIDER=fake

AGENT_LLM_PROVIDER=openai
AGENT_LLM_MODEL=cx/gpt-6-luna
AGENT_LLM_BASE_URL=http://localhost:20128/v1
AGENT_LLM_TEMPERATURE=0
AGENT_LLM_API_KEY=<کلید محلی؛ فقط در .env>
```

نکات:

- `JWT_SECRET` و `CONFIRMATION_HMAC_SECRET` را از هم جدا نگه دارید.
- کلید API مدل فقط سمت سرور و در `.env` محلی است؛ در مرورگر یا مخزن قرار نمی‌گیرد.
- برای Providerهای دیگر، `AGENT_LLM_PROVIDER=ollama` یا `openrouter` و متغیر مربوط به کلید همان Provider را مطابق `.env.example` تنظیم کنید.
- `APP_ENV=development` و `OTP_PROVIDER=fake` باعث می‌شوند کد OTP آزمایشی در پاسخ API برگردد. در Production این قابلیت غیرفعال است.

## ۳. اجرای LLM محلی

سرویس LLM محلی را قبل از FastAPI اجرا کنید و مطمئن شوید مدل تنظیم‌شده در دسترس است. مثلاً برای 9router:

```powershell
# سرویس 9router باید روی پورت 20128 در حال اجرا باشد.
curl.exe http://localhost:20128/v1/models
```

اگر سرویس در دسترس نباشد، صفحه چت کار می‌کند اما پاسخ Agent خطای قابل‌فهم دریافت می‌کند. هیچ درخواست مدل از مرورگر ارسال نمی‌شود؛ همه از بک‌اند عبور می‌کنند.

## ۴. ساخت دیتابیس دمو و داده‌های آزمایشی

از ریشه پروژه و در همان ترمینالی که `DATABASE_URL` را تنظیم کرده‌اید:

```powershell
$env:DATABASE_URL = "sqlite+aiosqlite:///./demo.db"
$env:PYTHONIOENCODING = "utf-8"
.\.venv\Scripts\python.exe -m scripts.seed_demo
```

Seed Script:

- فقط وقتی اجرا می‌شود که `DATABASE_URL` دقیقاً به `demo.db` در ریشه پروژه اشاره کند.
- Idempotent است؛ اجرای دوباره رکورد تکراری نمی‌سازد.
- هیچ دیتابیس موجودی را حذف، خالی یا Reset نمی‌کند.
- قبل از هر اتصال، مقصد را اعتبارسنجی می‌کند.

داده‌های ساختگی:

| مورد | مقدار |
|---|---|
| مدیر | `09120000001` / `DemoAdmin!123` — فقط دمو |
| بیمار | `09120000002` — ورود با OTP آزمایشی |
| پزشکان | دکتر سارا احمدی و دکتر امیر کریمی |
| خدمات | معاینه اولیه دندانپزشکی، ترمیم دندان، جرم‌گیری نمایشی |
| برنامه کاری | همه روزهای هفته، ۰۹:۰۰ تا ۱۳:۰۰، Slotهای ۳۰ دقیقه‌ای برای هر دو پزشک |

**رمزها و شماره‌های بالا صرفاً داده ساختگی دمو هستند و نباید در Production استفاده شوند.**

## ۵. اجرای FastAPI و صفحه چت

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

- صفحه چت بیمار: **http://127.0.0.1:8000/demo**
- Swagger (برای مدیر/مدیریت): **http://127.0.0.1:8000/docs**
- Health: **http://127.0.0.1:8000/health**

صفحه چت طراحی Responsive دارد و فونت وزیرمتن به‌صورت محلی از `/demo-assets` سرو می‌شود؛ بنابراین برای فونت به اینترنت وابسته نیست. منوی کنار عنوان شامل «گفت‌وگوی جدید» و «خروج از حساب» است.

## ۶. سناریوی ورود و دمو

### ورود بیمار از صفحه چت

1. آدرس `/demo` را باز کنید.
2. شماره `09120000002` را وارد کنید.
3. «دریافت کد آزمایشی» را بزنید. چون `APP_ENV=development` و `OTP_PROVIDER=fake` است، کد در کادر مخصوص دمو نمایش داده و خودکار پر می‌شود.
4. «ورود به گفت‌وگو» را بزنید.
5. یکی از درخواست‌های نمونه را بنویسید؛ مثلاً:
   > نزدیک‌ترین نوبت برای جرم‌گیری نمایشی را پیدا کن.
   یا:
   > دندونم پوسیده، چه خدمتی دارید؟ نزدیک‌ترین نوبت معاینه را بده.
6. ایجنت ابتدا خدمات/پزشکان/Slotها را از دیتابیس بررسی می‌کند و نزدیک‌ترین نوبت‌ها را به‌صورت کارت‌های قابل انتخاب نشان می‌دهد. انتخاب کارت فقط درخواست رزرو را به ایجنت می‌فرستد؛ تا زدن «تأیید و انجام» هیچ نوبتی ثبت نمی‌شود.
7. با «تأیید و انجام» یا «انصراف»، نتیجه واقعی نمایش داده می‌شود.
8. «گفت‌وگوی جدید» شناسه نشست، تاریخچه محلی و تأیید قبلی را پاک می‌کند.

### ورود مدیر

از Swagger در `/docs`:

- `POST /auth/login` با شماره `09120000001` و رمز `DemoAdmin!123`.
- توکن را در دکمه Authorize وارد کنید.
- ساخت بیمار/پزشک/خدمت/برنامه کاری و اتصال بیمار به حساب از همان Swagger انجام می‌شود. Seed Script داده‌های اصلی را از قبل ساخته است.

> برای نمایش مدیریت، Swagger کافی است؛ در این مرحله داشبورد گرافیکی مدیریت اضافه نشده است.

## ۷. تست‌ها

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

- مجموعهٔ کامل Python در آخرین اجرا: **۳۸۵ تست موفق**.
- تست‌ها از دیتابیس موقت استفاده می‌کنند و به LLM، SMS یا مرورگر واقعی وابسته نیستند؛ LLM در تست‌ها Fake است. یک اجرای جداگانهٔ مرورگر واقعی با fixture موقت و LLM Fake نیز انجام شده است (بخش UI).
- تست‌های امنیتی Confirmation، Replay، نشست/کاربر دیگر، هویت بیمارِ متصل، نبود حساب متصل، لغو/جابه‌جایی نوبت دیگران، سقف مراحل Graph، `slots`، رد نوبت گذشته با منطقهٔ زمانی Asia/Tehran، رزرو هم‌زمان و جست‌وجوی فارسی را پوشش می‌دهند.

### تست دودِ UI (اختیاری، jsdom)

این تست بخشی از `unittest` نیست و به مرورگر واقعی وابسته نیست. `jsdom` را خارج از مخزن نصب کنید:

```powershell
npm install --prefix "$env:TEMP\dental-jsdom" jsdom@26
$env:NODE_PATH = "$env:TEMP\dental-jsdom\node_modules"
node tests\ui\chat_smoke.js
```

این تست ورود OTP، پاسخ عادی، قطع شبکه و Retry ایمن، Confirmation، خطای 409/422، نتیجهٔ نامشخص پس از تأیید، کارت‌های Slot، انتخاب Slot و انقضای نشست (401) را شبیه‌سازی می‌کند.

علاوه بر تست سنتزی، یک اجرای واقعی مرورگر با fixture موقت، OTP Fake و LLM Fake انجام شد. این اجرا ورود بیمار، نمایش سه کارت Slot، انتخاب Slot، متن Confirmation داده‌محور و خطای شبکه پس از تأیید را در یک مرورگر واقعی پوشش داد؛ UI پس از نتیجهٔ نامشخص، درخواست نوشتاری را دوباره ارسال نکرد و گزینهٔ «بررسی نوبت‌های من» را نمایش داد. این اجرا خودکار نیست، در CI نیست و Playwright در پروژه نصب نشده است.

## ۸. رفتار امنیتی و خطاها

- هویت بیمار فقط از حساب واردشده و پروندهٔ متصل (`patients.user_id`) گرفته می‌شود؛ شناسه یا کد ملی ارسالی مدل/کلاینت برای حساب بیمار معتبر نیست.
- Confirmation سمت سرور و پایدار است و به کاربر، نشست، نام ابزار، آرگومان‌های نمایش‌داده‌شده و شناسهٔ Tool Call گره خورده است؛ توکن منقضی، مصرف‌شده، متعلق به نشست دیگر یا دارای دادهٔ تغییرکرده رد می‌شود.
- متن Confirmation از نام واقعی پزشک/خدمت/نوبت و تاریخ و ساعت دیتابیس ساخته می‌شود؛ نبود رکورد یا تغییر وضعیت، به خطای Catalog‌شده و پاسخ امن تبدیل می‌شود.
- آزاد بودن Slot پیش از نمایش Confirmation و دوباره در زمان اجرا بررسی می‌شود؛ مجوز نیز در زمان اجرا دوباره کنترل می‌شود. اگر نتیجهٔ شبکه پس از تأیید نامشخص باشد، UI توکن را دوباره نمی‌فرستد و گزینهٔ «بررسی نوبت‌های من» می‌دهد؛ برای پیام‌های عادی Retry ایمن دارد.
- نوبت‌های گذشته با ساعت دیواری Asia/Tehran رد می‌شوند؛ Slot دقیقاً مساوی زمان جاری نیز گذشته محسوب می‌شود. این بررسی هم در رزرو و هم در جابه‌جایی و پیش از صدور Confirmation اعمال می‌شود و به ساعت واقعی اجرا وابسته نیست (زمان قابل تزریق است).
- Graph سقف ۱۲ مرحله دارد و خطای Recursion به پاسخ فارسی امن (HTTP 200) تبدیل می‌شود، نه ۵۰۰.
- SQLAlchemy Echo به‌صورت پیش‌فرض خاموش است تا پارامترهای SQL حاوی شناسه/اطلاعات بیمار در لاگ ثبت نشوند. برای دیباگ محلی می‌توان `SQL_ECHO=true` را صریحاً تنظیم کرد.

## محدودیت‌های دمو

- SMS واقعی غیرفعال است؛ فقط Provider Fake توسعه فعال است.
- صفحه چت یک صفحه دمو است، نه داشبورد کامل مدیریت.
- تاریخچه گفت‌وگو در سرور ذخیره نمی‌شود؛ فقط Confirmation پایدار است.
- سرویس LLM محلی باید در دسترس باشد؛ کلید API نباید در مرورگر یا Git قرار گیرد.
- Playwright/تست مرورگر خودکار در CI وجود ندارد؛ اجرای واقعی انجام‌شده با fixture موقت و LLM Fake بود، نه Provider واقعی.
- رزرو هم‌زمان در SQLite با Partial Unique Index تست شده است؛ برای Deployment چند-Worker به یک دیتابیس و تراکنش مشترک نیاز است.
- اگر CORS لازم شد (Frontend جداگانه)، باید صریحاً در FastAPI تنظیم شود؛ صفحه `/demo` روی همان Origin است و CORS لازم ندارد.
